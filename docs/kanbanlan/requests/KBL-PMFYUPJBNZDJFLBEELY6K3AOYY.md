# Build and audit deterministic guide collections

- Kanbanlan: `KBL-PMFYUPJBNZDJFLBEELY6K3AOYY`
- Canonical home: `github`
- Canonical request: [#24](https://github.com/jmitchel3/crawlson/issues/24)

## Request

Outcome: compile multiple verified Crawlson run/journey pairs into one deterministic, app-ingestible Markdown guide collection while keeping evidence-backed bugs and incomplete outcomes visible in a separate review surface.

Acceptance criteria:

- Add a strict, bounded, versioned collection manifest and schema with stable collection, topic, and guide identities; deterministic ordering; portable relative input paths; and no traversal, symlink, duplicate, or ambiguous-identity behavior.
- Add equivalent `crawlson` and `clson` commands to build and check a collection offline without launching a browser.
- Reuse the run renderer's provenance, action authorization, evidence, and digest validation. A reader-facing guide may come only from a passed, fully verified run. Failed runs surface structured findings; blocked, error, cleanup-failed, drifted, or tampered inputs remain explicit and cannot appear as verified guides.
- Emit a neutral wiki tree with a root index, topic indexes, one Markdown page per verified journey, and the same digest-verified red-box/dimmed focused images. Emit review findings separately so applications can publish only the guide subtree.
- Emit a schema-validated collection report that binds every page and image to the manifest, journey revision/source digest, run/report digest, and generated output digest.
- Make generation deterministic, atomic, and idempotent. Preserve and reject conflicting output. The check command must report missing, changed, unexpected/orphaned, stale, dead-linked, and unindexed generated files without rewriting them.
- Add tests for pass/finding/blocked/error mixtures, aliases, link integrity, tamper, traversal, symlinks, duplicates, stale output, idempotence, and focused-image byte identity. Extend the self-contained demo and documentation with the complete collection workflow.
- Bump the product minor version and retarget release documentation/request metadata without publishing owner-gated artifacts.

Out of scope: hosted publication, application HTML/theming, authentication adapters, generic buttons or typing, mutation/fixture execution, autonomous model judgment, and destructive in-place replacement of an existing collection.

## Decisions

- Keep collection generation in the Rust core as an offline composition layer.
  It launches no browser and distrusts any prior `render/` directory: every raw
  run is snapshotted and passed back through the existing renderer with its
  exact journey source.
- Use an all-or-nothing public surface. Only an entirely `guide_ready`
  collection receives a public root/topic/guide tree. Findings and blocked
  entries receive a separate review tree; any renderer error produces only the
  machine-readable command report and installs no directory.
- Aggregate every identifiable entry before applying deterministic precedence:
  error, then unavailable, then findings, then ready. Preserve renderer reason
  codes such as tamper, run, and cleanup failures on their exact entries.
- Make `guide-collection.json` the neutral rendering boundary. It binds the
  manifest/snapshot, topic/audience, journey/run/report, page/image digests, and
  ordered step instructions with explicit observed-versus-executed claims.
  Markdown pages are rendered from that same step model.
- Treat path portability and publication as safety properties. Reject empty,
  aliased, traversal, reserved-device, trailing-dot, control, symlink, and
  file/directory-colliding paths. Enforce collection-wide input and retained /
  generated byte budgets before allocation or staging.
- Install only with a same-filesystem no-replace directory rename on supported
  macOS, Linux, and Windows targets; fail closed elsewhere. Existing output is
  either byte-identical or preserved and rejected.
- Keep `guides check` strictly read-only, including suppressing periodic updater
  network/state work. Legitimate public-to-review or review-to-public changes
  are stale exit 3, while independently corrupted links, bytes, or reachability
  remain integrity error 4.
- Bump the product to 0.7.0 and retarget the owner-gated release request without
  publishing artifacts.
- Repair the repository's stale Kanbanlan projection binding to the live
  Project 2 board, then reconcile the three canonical open requests and restore
  this claimed card's In progress projection state.

## Delivered result

Crawlson 0.7.0 adds equivalent `crawlson` / `clson guides build` and `guides
check` commands, strict v1 collection schemas, deterministic reader and review
trees, structured application ingestion, full provenance, honest mixed-status
reporting, focused-image preservation, and an end-to-end demo.

The owner-gated signed release request now targets 0.7.0. Publishing remains
blocked on the explicitly recorded license, namespace, production signing-key,
and exact-release approvals. Authentication, generic input/buttons, mutations,
hosted publication, application theming, and agent judgment remain separate
follow-up outcomes.
